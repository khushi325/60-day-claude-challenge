## 🐛 Debugging

When an issue occurred, the development process stopped at that point until the problem was understood and resolved.

The debugging cycle was:

1. Identify the problem.
2. Inspect the error.
3. Determine the root cause.
4. Apply the fix.
5. Restart/rebuild the application.
6. Re-test the affected functionality.
7. Continue only after verification.

## 📚 What I Learned

- New features should be developed with existing functionality in mind.
- Regression testing is essential when building incrementally.
- Free-tier tools can be sufficient for a focused V1.0.
- Refactoring during development can prevent technical debt from growing.
- Small implementation steps make debugging much easier.
- Scope discipline becomes increasingly important as the project grows.

## 💡 Biggest Learning

> **Adding a feature is only successful if the features that already worked continue to work.**

Development isn't just about making something new—it is also about protecting what has already been built.
