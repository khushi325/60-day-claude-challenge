📐 Architecture overview

Eight specialized agents share state through a running history[] array. The Planner and Executor run once to establish the outline and first draft. Then an improvement loop repeatedly calls Evaluator → Critic → Improver → Memory Manager — each call is a fresh, live request to the Claude API carrying forward the prior round's score, critique, and draft as context. A Safety Monitor screens each new draft. After every round the app runs a deterministic stop-check (plateau, then threshold, then hard cap) purely on the model-reported score — no fixed round count exists anywhere in the code. Once a condition fires, control branches to the Final Reviewer, which never edits content itself — only certifies and lightly polishes the last approved draft.

💡 Extension ideas

  • Add a Fact-Checker agent with live web search grounding, feeding citations back to the Critic.
  • Persist history[] to a vector store so Memory Manager learns across runs, not just within one.
  • Add a human-in-the-loop approval gate before Final Reviewer publishes.
  • Parallelize Evaluator + Safety Monitor calls per round to cut latency.
  • Let the Critic propose *which* rubric dimension to prioritize next round, adapting the Improver's prompt dynamically.
  • Swap the stop-check to a multi-metric Pareto frontier (accuracy AND readability AND SEO) instead of a single score.

🚀 Further prompts to build more advanced systems

  • "Add a Fact-Checker agent that uses web search to verify each claim before scoring."
  • "Turn this into a multi-document research synthesizer with a Source Ranker agent."
  • "Add branching: if Safety Monitor flags content, route to a Redactor agent instead of Improver."
  • "Persist run history in localStorage and let me compare pipelines across runs."
  • "Add a cost/latency tracker per agent call and a budget-aware early stop."
