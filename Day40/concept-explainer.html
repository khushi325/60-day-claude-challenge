How this was built

The system prompt ("brain")

The model is instructed to act as a warm, funny concept explainer for students. It always returns strict JSON (topic title, one-line analogy, a simple SVG-friendly diagram spec, layered text sections, common mistakes, and a "go deeper" prompt) so the UI can render a purpose-built card instead of a wall of chat text. Constraints include: refuse harmful/unrelated requests politely, ask a clarifying follow-up only when the topic is truly too vague (e.g. a single ambiguous word), never fabricate facts it's unsure of, and match tone/depth to the selected level (beginner/intermediate/advanced).

Why this UI

A generic chat bubble UI would hide the thing students actually need: a visual anchor. This layout leads with a hand-drawn-style diagram and a highlighted analogy line before any paragraph text, mirroring how a good tutor sketches on a napkin before lecturing. The notebook/sticky-note aesthetic (dashed borders, rotated cards, highlighter strokes) signals "informal learning tool" rather than "corporate chatbot," which matches the playful tone requested.

Extending this

  • Memory: store past topics in localStorage or a backend, and feed a short "things you've already learned" list into the prompt so explanations can build on prior sessions.
  • Tools: add a web_search tool call before generation for fast-moving topics (current events, latest tech) so explanations stay accurate.
  • Multi-step flow: turn the "go deeper" section into a real follow-up input that re-calls the API with conversation history, enabling a Socratic back-and-forth instead of one-shot answers.
  • Quizzing: add a "test me" button that calls the API again asking for 3 quick check-for-understanding questions based on the same JSON output.
